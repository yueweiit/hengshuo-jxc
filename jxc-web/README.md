# 恒烁进销存 · 前端（jxc-web）

Vue 3 + Vite + TypeScript + Element Plus + Pinia。设计依据见 `../docs/`。

## 运行

```bash
npm install
npm run dev        # 真实后端 http://localhost:5173
npm run dev:demo   # 独立演示 http://localhost:5174
npm test           # 真实 Mock handler 的隔离回归（Node 22.15+，已在 Node 26 验证）
npm run build      # 类型检查 + 打包
```

## Mock 与真实后端

开发与生产构建默认连接真实后端。浏览器始终请求同源 `/api/v1`；开发代理目标由 `VITE_API_TARGET` 配置，生产反向代理应将 `/api` 转发到后端。真实模式启动会注销本应用旧 `mockServiceWorker.js`，仅清理 MSW 命名缓存，受旧 worker 控制时先刷新；不会删除 localStorage、附件或用户业务数据。真实构建不复制 MSW worker，也不打包 Mock 业务数据库。

演示只能显式运行 `npm run dev:demo`（独立端口 5174）或 `npm run build:demo`；`VITE_USE_MOCK=true` 单独不能开启普通开发/生产 Mock。演示数据仅存在该浏览器 origin 的本地存储，不与 PostgreSQL 混用。下列账号仅用于演示模式，真实账号由隔离环境或正式管理员配置。

测试中的原 Mock 业务回归与新增真实 transport/页面契约分开，Node 测试不等同于 PostgreSQL 集成测试或真实浏览器验收。

## 页面范围

- 第 1 批（可用）：登录、工作台、审批待办、通知；国家列表 / 复制向导 / 国家详情 / 模板；
  主体、仓库、门店；用户、角色、审批规则、单据关注人；基础档案全部页面；审计日志。
- 第 2 批（可用）：中国采购到 MX 入库，数量与成本可追溯。
  - 采购：采购单列表 / 详情（执行进度）、国内收货登记、出口节点。
  - 物流：运输批次列表 / 详情（数量分桶与恒等校验、节点时间线与更正、柜号历史、换柜、暂缓、派送、费用、附件）、
    暂缓派送、派送单、MX 实收（手机可用，扫码定位）、到货差异处理、物流费用（暂估 / 实际）、在途看板。
  - 库存：库存查询（批次抽屉、冻结、成本追溯）、库存流水、冻结管理、调拨单（分次实收、差异关闭）、
    盘点单（快照锁定、扫码计数、差异审批、过账）、库存上下限、库存预警。
  - 成本：入库成本（缺汇率不能确认、批量确认、批次成本追溯）。
- 第 3 批（可用）：销售、收款授信、应付、退货退款。
  - 销售：代客录单（三级定价与价格快照）、订单详情（审批 / 履约 / 付款三种状态、出库检查、销售单据与收款凭证）、出库确认、签收、价格表、门店日报。
  - 往来：收款登记与到账确认、授信规则、应收、核销、客户对账单与客户往来；应付账单、付款、预付、核销、供应商往来。
  - 退货：销售退货（审批、实收、验货、账款）、退款、采购退货、货损索赔。
- 第 4 批（可用）：库存与订单联合分类、补货待办、费用分摊、成本调整、费用登记、单品利润、AI 解释；
  账套期间、科目、期初、凭证映射、业务事件、凭证、账簿、试算平衡、子账核对、结账、财务报表；导入中心与导出任务。
  智利作为第二国家已启用，业务数据与墨西哥分开。批次划分见 `docs/README.md`。

### 第 2 批演示场景

种子数据由 `src/mock/scenario.ts` 调用业务函数逐步生成，数量、流水、待办、成本彼此一致：

- PO-A（P0001、P0002）：两次派送实收。第一批实收日没有已确认汇率，入库成本为「待补汇率」；
  第二批有破损冻结和 2 件短缺差异；之后从中心仓调拨到一号店。
- PO-B（P0003、P0004）：保温杯海运批次延误未到港；台灯批次到港后换柜、放行、部分暂缓、部分派送在途，
  可用 wh01 在「MX 实收」完成验收。
- PO-C 为草稿；PO-D 为大额采购，待 lead01 审批。
- 上下限分别触发「低于下限」「高于上限」「缺货」预警。

### 第 3 批演示场景

同样由业务函数生成，和上面的库存连在一起：

- 基础价、A/B 级等级价，以及客户 601 对 P0001 的专属价。601 允许赊销，额度 80,000。
- 门店现款订单已收款并出库，应收自动核销。另一张现款单没有销售单据，出库停在草稿。
- 批发赊销先出一部分，应收只记已出库金额，额度占用不变。超过 5 万的赊销单停在待审批。
- 采购行（CNY，未付）和清关费（MXN，已付款核销）各有一张应付账单。

### 第 4 批演示场景

- 中心仓 P0001 库存高、已审批订购件数不高，分类为滞销候选；没有订单的缺货商品保持普通，不会因为库存为 0 变成畅销。
- P0004 低于下限，生成一条补货待办。同一预警再次生成不会重复。
- 一笔 MXN 费用已有数量分摊草稿；关联批次待补汇率，补齐成本后才能确认，分摊明细合计等于费用本位币金额。
- 一笔已确认收款生成凭证，由管理员编制、财务记账。其余业务事件留在「未生成」，结账检查不会放行。
- 智利用本国现金和 CLP 价格完成一笔现款销售并出库，不改变墨西哥库存。账号 `cl01`。

## 目录

  components/   CrudPage、附件、审批面板等通用组件

## 版本说明

- TypeScript 固定 5.9：vue-tsc 3 依赖 TS 的 JS API，TS 7 不再提供。
- MSW 3 中未匹配请求的选项名为 `onUnhandledFrame`（旧版为 `onUnhandledRequest`）。
