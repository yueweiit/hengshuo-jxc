# 真实后端一致性基础实施方案

> **For agentic workers:** 后续执行使用 `superpowers:subagent-driven-development` 或 `superpowers:executing-plans`，按阶段验收。本文件初版为方案审阅稿；现已按用户授权实施 M0–M5，实际范围见 [M0/M1](../../backend/acceptance-m0-m1.md)、[M2](../../backend/acceptance-m2.md)、[M3](../../backend/acceptance-m3.md)、[M4](../../backend/acceptance-m4.md) 和 [M5 验收记录](../../backend/acceptance-m5.md)。M5 完成隔离合成环境的清点、停写、备份恢复、切换后新增数据恢复和双国原页面验收；实际生产目标、期初及历史范围仍须另行确认实施。

**Goal:** 沿用现有接口、业务状态与规则，将期间锁、成本总账、金额数量一致性和权限落实为服务端命令、PostgreSQL 事务及数据库约束。

**Architecture:** 沿用 `docs/00` 的模块化单体；强一致操作在一个 PostgreSQL 事务内通过模块 API 同步完成。现有事务事件表承担可靠异步处理，凭证分录和成本变动保存事实，余额、利润和报表作为可校验的投影。

**Tech Stack:** Spring Boot、Spring Security、MyBatis-Plus、Flyway、PostgreSQL、MinIO；金额计算使用 Java BigDecimal；真实 PostgreSQL 集成测试使用 JUnit 与 Testcontainers。工程初始化阶段锁定各依赖的受支持 GA 版本、兼容组合与容器摘要，不使用浮动 `latest` 或预览版本。

日期：2026-10-15。基线：目前只有 `jxc-web`，不存在 `jxc-server`；当前业务由浏览器 MSW/localStorage 实现。上一轮验证为 111 条 Mock 回归通过，不能作为数据库事务或并发的验收结果。

## 1. 方案选择与本轮边界

推荐直接落地既定 Java 模块化单体。同库同步事务可以覆盖库存、应收、信用和成本，保留前端契约及模块边界；部署规模变化后仍可先扩应用实例。

另外两种路线不作为本次推荐：将 TS Mock 包装为网络服务，虽然起步快，但仍需重写持久化、事务和金额实现，且偏离既定技术选型；立即拆微服务则会把现有原子操作变成分布式一致性问题，增加消息、补偿和运维成本。

本方案包括基础档案、审批、附件等主流程必需依赖；不扩展外部支付执行、税务、法定合并报表、外部审批、SSO 或新的销售/物流业务模式。AI 只保留受控只读取数边界，模型供应商接入可以后置。

### 2.2 两项需要显式记录的技术细化

1. 原文档写雪花 bigint ID，当前 Vue 和 Mock 多处使用 `Number(id)`。推荐一期使用 PostgreSQL 共享 sequence 生成 bigint，API 继续返回安全整数，约束 `id <= 9007199254740991`；不把任意 Long 直接交给前端。此项在 M0 记录为对原雪花假设的调整。将来必须使用完整 64 位分布式 ID 时，再独立设计字符串 ID 迁移。
2. 金额存储、JSON 字段形状保持；服务端从原始十进制 JSON 解析 BigDecimal，不经 double。前端显示和预览不是账务依据。超出前端可靠显示范围的数值由 DTO 边界拒绝并给出错误，范围通过现有业务样本在 M0 明确；不得静默舍入或以字符串偷偷替换字段类型。

## 3. 工程边界与拟新增文件

沿用 `docs/00` 的 `jxc-server/jxc-common`、`jxc-module-{sys,md,pur,lgs,inv,sal,ar,ap,rtn,cst,fin}`、`jxc-app`。每个模块保留 `api/controller/service/domain/mapper/event` 包，领域服务定义事务边界。

跨模块接口放在所属模块的 `api` 包。Maven 依赖出现环时，将该模块 API 提取为其独立 API 子构件，包名与所有权不变；不把全部业务接口塞进 common，也不允许跨模块 Mapper 访问。启动模块装配实现，领域模块仅依赖所需 API。

## 4. 数据库共同底线

### 4.1 归属、精度和引用

- 国家业务表 `country_id NOT NULL`；财务与成本表另有 `book_id NOT NULL`。主体/仓店/资金账户决定账套，客户端只能选择已授权且一致的归属。
- 父表提供 `UNIQUE(country_id,id)` 或 `UNIQUE(country_id,book_id,id)`，子表使用对应复合 FK。科目、期间、成本和来源不能只按裸 id 引用；本国经营商品通过国家 SKU 关联，全局商品主档保持共享。
- 账套未启用、未配置或归属不能唯一解析时阻断。不能照搬 Mock 的“没有账套就不锁期间”或“取第一本 ACTIVE 账套”。跨主体/跨账套调拨未配置会计处理时阻断执行并列出缺项，不猜内部结算政策。
- 金额 `numeric(20,4)`、基础数量 `numeric(18,4)`、汇率 `numeric(18,8)`；单位成本与除法中间精度建议 `numeric(38,12)`，最终金额按币种逐行 HALF_UP 再汇总。
- 日期使用 `date`，操作时间使用 `timestamptz`；业务日期按仓店或国家时区解析。期间不重叠，账套、年度、期号唯一；期间范围使用排斥约束，所需 `btree_gist` 由迁移身份安装。
- 请求中的余额、可退量、可核销量、来源价格、本位币金额不作为可信事实；服务端重取来源和确认版本。

### 4.2 约束放置

本行的不变量使用 NOT NULL/CHECK，例如非负数量、有效汇率、`used <= amount`、`consumed + released <= reserved`、`outbound + cancelled <= base_qty`。普通申请金额严格为正；实收分类允许零；冲销/调整按独立类型允许规定符号，不能给全部财务行统一加正数约束。

跨行合计和并发累计不能写成引用别表的 CHECK：用受锁来源余额、条件 UPDATE、唯一索引或在提交时检查的约束触发器。分仓合计、凭证表头/行合计和借贷平衡须覆盖 INSERT/UPDATE/DELETE，并锁同一父单，提交时复核。

幂等和业务唯一性双重保障：

- `sys_idempotency UNIQUE(country_id,user_id,key)`，并比较 method、规范化 endpoint、可信 book 与请求 hash。
- `sys_biz_event UNIQUE(country_id,event_type,source_type,source_id,event_seq)`；消费 `UNIQUE(event_id,consumer)`。
- `inv_stock_txn UNIQUE(country_id,source_type,source_line_id,txn_type,seq)`；MX 实收批次的来源实收行唯一。
- 来源单据内的来源行唯一，例如 `(receipt_id,order_line_id)`、`(shipment_id,source_line_id)`、`(delivery_id,shipment_line_id)`；跨单累计上限另外锁来源父行。
- 应收来源唯一；核销反向记录对原核销唯一；退款支付事实对退款单唯一。
- AP 有效来源占用用独立 `ap_source_claim` 记录，保存规范化源、数量、账单及释放时间。整笔物流费有效占用部分唯一；采购来源允许分次开票，锁来源额度防止累计超量。不能在子表部分索引中引用父账单状态。
- 退货结算有效版本对退货单唯一；贷项唯一键包含结算版本与用途，允许同一次退货分别冲应收和形成可退款金额。

### 4.3 运行身份

Flyway 迁移身份与应用身份分离；应用无 DDL、无 BYPASSRLS、不是表所有者。国家业务表同时启用并强制国家 RLS 作为漏过滤兜底；服务层仍实施细粒度来源权限。审计与事实流水只追加，运行角色没有 UPDATE/DELETE/TRUNCATE 权限；需更正的记录追加反向事实。

## 5. 一个命令如何提交

通用顺序：建立可信上下文 → 先取得授权共享闸门、再读取权威授权及 epoch → 取得幂等记录 → 按 ID 排序取得账套闸门 → 校验期间 → 客户/往来币种余额 → 源单和目标单 → 仓作业守卫 → 按仓/SKU 排序的库存汇总 → FIFO 批次和成本 → 凭证及余额键 → 业务状态、审计、outbox、幂等结果一起提交。不得在等待授权闸门之前读取权限，醒来后继续使用旧结果。

全路径遵循同一锁分类及排序。命令协调器先收集跨模块涉及的锁对象，取得后复核版本和来源；发现依赖集合变化则整事务重试，不能中途倒序补锁。普通编辑用 version CAS，动作校验当前状态与审批哈希；版本校验不替代库存、资金和来源余额锁。

数据库隔离级别默认 READ COMMITTED，配合明确锁点；死锁、序列化和锁超时按可重试错误分类，有限次整事务重试，失败返回原业务错误或 409。不能从“已经扣库存”的半段继续，也不能在事务中等待用户、上传文件或调用模型。

### 5.1 幂等、重放及失败

幂等占位与业务使用同一事务。相同 key 并发通过唯一索引等待首笔提交；同 hash 返回首次业务效果，不同路径或内容返回 409。事务回滚会一并撤销占位，允许原 key 安全重试；提交成功但响应断线则读取已提交结果。等待超过请求预算返回可重试的冲突，不能另起执行。

成功记录保存结果资源引用及业务结果快照。重放时先校验当前功能/来源权限，再按当前字段策略序列化，不能直接返回过去缓存的敏感 JSON。前端的 key 在同一操作意图和重试间保持不变，成功或用户改变意图后才换 key。

### 5.2 事务事件与恢复

沿用 `sys_biz_event` 事务 outbox，不引入消息中间件。业务确认必须同时写事件；独立 worker 通过短事务租约领取，执行事务重新按统一顺序取得账套与消费锁。消费记录和该消费者的写入同事务提交，崩溃后可恢复。只能保证幂等效果，不能声称消息只投递一次。

财务消费者不假设成本已先完成；缺成本、汇率、辅助项或已复核映射时记录明确原因，保留重试。主事务完成回滚并释放锁之后，才用独立短事务记录 attempt/错误/待办；只保留诊断，不保留半张凭证或部分库存变动。条件比较消费版本，避免旧失败覆盖已成功的新尝试。

生产 GET 只查询，不运行 `syncEvents` 补事件或业务重算。分类和利润投影允许异步，但响应显示取数版本和是否落后；结账核对读取事实或已验证一致的投影，不接受过期缓存。

## 6. 期间锁与结账

### 6.1 共同闸门

所有影响账套业务的写事务先对 `fin_book` 行 `SELECT ... FOR SHARE`，持有到提交。结账、反结账及影响历史解释的账套配置从开始就对同一行 `FOR UPDATE`；不先共享再升级。共享闸门允许正常业务并发，排他闸门只短时阻断同账套写入，其他国家/账套不受影响。

不得在每笔业务末尾 UPDATE 同一个 book 行来递增全局 revision，否则会造成共享锁升级、死锁和不必要串行化。检查指纹由本次核对来源版本生成。

期间判定在取得闸门后执行。承载业务日期的业务、库存、成本及凭证事实表增加 DB period guard：写入时锁同一账套闸门，检查本行国家/账套/业务日期与期间一致、期间开放；更新业务日期同时检查旧归属期间。余额和当前成本等投影按其本次命令及追加事实的开放期间校验，不套用旧批次入库日期。这样遗漏某个 Java 校验的 Mapper 也不能写回已结期间。系统诊断和任务租约不属于账务事实，不以原业务日期阻断其错误记录。

合法跨期更正的差额、冲销事实记在开放期间；历史原单的“被替换/已冲销”展示状态及反向关联优先由追加关系派生。确需更新历史关联元数据时只允许严格白名单字段，并关联本次开放期命令；不能把这种关系维护误当成重写历史金额而全部拒绝，更不能借例外修改旧日期、数量、金额、币种、汇率或来源事实。

### 6.2 结账和反结账事务

结账取得排他闸门后重新执行全部检查，读取此前写事务已提交的数据，不能信任页面旧检查。未生成/失败事件、未审核/记账凭证、借贷不平、缺成本/汇率、未确认分摊、未过账盘点等必须阻断；财务允许确认的差异绑定检查指纹与代次，结构错误不能豁免。

有待处理事件就返回详情并释放闸门，不能拿着排他锁等 worker。通过后一次提交 BALANCE、REPORT、RECONCILE 快照及其来源版本、关闭当前期间并按既有规则开放下一期间。快照键为 `(period_id,close_generation,snapshot_type)`，同一次重复结账不增加代次。

反结账校验独立权限和原因，检查后续已结期间及余额依赖；记录旧快照引用和影响，开放原期间，废除旧差异确认并使后续开放期间投影失效/重建。再次结账生成新代次，旧代次只读保留。对已结期间执行检查不能改变 CLOSED。

## 7. 成本和总账的事实模型

### 7.1 成本只保留一套依据

- 沿用 `cst_inbound_cost`，冻结已确认的采购原币、汇率、本位币采购金额、初始单位成本和方法版本。当前单位成本拆到 `cst_batch_valuation_current` 投影表，API 仍返回原 unitCost 字段，不回写已结原入库事实。
- 将当前 `valuationHistory` 规范化为 `cst_valuation_change`：保存 batch、日期、数量基础、金额/单位差额、来源/序号、期间、反向关联与操作人，来源组合唯一，追加不覆盖。
- 当前成本投影的更新绑定本次开放期估值变动及来源；受控重建只从有效事实重算，不能任意修改投影来代替成本调整。其守卫检查本次调整期间，而非原批次的历史入库日期，避免合法后到费用被旧期间锁拒绝；历史核对仍读截至日事实或结账快照。
- 沿用 `cst_cogs` 的单一来源行总成本，新增批次消耗组成表；移动平均的计价池组成另存，使“实际消耗批次”和“平均计价依据”可分别追溯，不错误约束两者为同一组成。
- 同 SKU 出库的全部行在同一锁定计价池下计算；实际批次总量等于出库基础数量。缺汇率保留 PENDING_RATE，退回来源缺成本保留 PENDING_SOURCE_COST 及完整度，不能填零；后补只能完善未定成本，已完整快照不可重估。
- 分摊按已确认本位币金额，尾差归最大金额行，并列按稳定批次 ID；有效 CONFIRMED 分摊对费用唯一。暂估关联在实际费用待汇率时即被占用，另一实际费用不能抢占。
- 实际费用仍走原确认恢复；原分摊、新有效分摊、在库差额和净已售 COGS 调整同事务提交，重复执行不再变化。后到费用跟随已退回批次，避免把退回库存仍计入净已售。
- `costAtDate` 按初始事实和截至日追加变动计算，不能用今天单价回算过去。历史无证据的记录保留缺失状态，迁移不能伪造。

### 7.2 凭证分录就是总账事实

不新增同义总账流水表。沿用 `fin_voucher/fin_voucher_line`、`fin_account_balance`；已记账及已冲销原凭证的分录金额、日期、科目、币种、汇率、辅助项和来源不可修改或删除，DB 触发器兜底。冲销追加反向凭证，原凭证仍参与汇总；原单存在待审核冲销时也禁止第二张。

记账锁凭证、校验已审核及编制/审核分离，再原子更新状态和余额。`source_event_id` 唯一，分录 `(voucher_id,seq)` 唯一；余额按账套/期间/科目/规范化非空 aux_key/币种唯一，使用原子 UPSERT。辅助项必须与科目配置及授权来源一致。

较早开放期间补记时，同事务按顺序更新受影响的后续开放期间期初和期末；确认期初只计一次，已结期间读取对应代次快照。余额可从记账分录与确认期初重建，重建走显式维护任务，不能在 GET 时删建。

采购事件只承接采购本位币成本，物流事件承接费用及实际差额，已售重分类为库存转 COGS，不能再次确认应付。应付账单确认是否产生暂估转正式分录由复核映射明确，不能同一采购或运费重复入账。自动生成只到待审核，不能自动记账。

零差额实际费用、无记账影响事件需在映射复核时明确“无需凭证”的处理结果与页面显示；不强造零凭证，也不让无法生成的零额事件无限堵结账。此项作为显式契约补充评审，不能私自改动已存在事件状态含义。

## 8. 金额数量必须同步的六条事务

1. **销售审批/改单/取消**：审批关键字段与规则版本校验，库存预留、信用预占、行/分仓状态一起提交。保留原行 ID 和已履约历史，超额/逾期例外缺有效审批保持阻断。
2. **出库确认**：本单预留消耗、汇总和批次扣减、成本组成、应收、信用预占转换、本单预收自动核销、出库状态、审计与事件一起提交。客户币种余额为共同锁点，转换本单预占不重复占信用。
3. **收付款与核销/撤销**：每一动作分别是短事务。来源和目标都锁定，核对同一客户/供应商及币种，不能挪用其他订单已分配现款；撤销追加反向记录并恢复资金、往来、信用和分配。跨币种保存账单、付款各自本位币快照及真实 fxDiff，改汇率不改历史。
4. **退货与退款**：申请占用可退量（含审批中），验货才增加可售/冻结库存并继承原出库成本，账款处理按原成交价生成冲应收或可退款贷项。少收按原原因和后续到货流程处理，不能在仍待收时自动释放全部余量；最终结算/关闭时释放剩余申请占用。退款申请与贷项核销竞争同一可退款余额，支付只登记事实和有效证据，不执行外部打款。
5. **采购退供/开应付**：国内与境外数量上限分开；国内退供同时回写原国内来源、减少可出口量，境外退供按指定库存批次出库；贷项、数量和状态同事务。应付按服务端原价和规范化来源额度建单，作废同步释放占用。
6. **收货→出口→发运→暂缓/派送→境外实收/调拨**：请求内重复来源先拒绝，跨请求锁来源额度条件更新。境外实收同时提交四类实收守恒、批次/冻结、在途桶、采购回写、成本来源及事件；沿用当前派送实收方式，不顺手扩展多次实收。调拨按持久化调出批次分配入库，历史分配不足拒绝且不增加累计量。

库存汇总与批次均有非负 CHECK；预留、冻结和实物在一个 UPDATE 中保持 `reserved + frozen <= on_hand`。例如预留使用条件 `UPDATE ... WHERE available >= :qty RETURNING id` 并检查影响行数；出库同时消耗本单预留和实物，不能先扣实物触发约束后再释放预留。

盘点开始和库存动作共用仓/SKU 作业守卫。盘点开始在短事务中原子建立范围锁和数量快照，人工计数期间不持 DB 长事务；后续变动在同一守卫下检查持久范围锁并拒绝。防止“检查没有盘点后，另一请求开始盘点”的竞态。

## 9. 服务端权限与收权

Spring Security 验证真实会话；密码 BCrypt，令牌只存摘要并设置到期与撤销，不能迁移演示明文密码。国家头仅是用户选择，不能成为授权依据；主体、账套和来源归属从数据库验证。平台/国家管理员、功能 `*` 不自动获得业务范围。

权限分四层：功能权限、国家授权、数据范围、字段权限。列表/搜索/详情/分页计数/汇总/导出/AI/审计/附件/写响应/幂等重放共用查询及序列化策略；不可见 ID 返回 404，功能缺权返回 403。只读资源不生成通用写入口。

- 范围 SQL 按 COUNTRY_ALL、ENTITY、STORE、WAREHOUSE、BOOK 正向展开；仓授权不能反推主体或全账套权限。来源链显式登记，未知类型拒绝；多来源金融单据要求全部来源可见，分仓订单按授权行重新算数量。
- 有效期按数据库时间左闭右开校验。授权缓存包含版本并不能跨起止边界；关键命令先对 `sys_authz_epoch` 策略守卫取共享锁，再读取当前权限。角色/范围/字段修改从事务开始直接取排他锁，重新校验操作者上界，不走普通共享锁再升级。全局身份/账号停用另有全局守卫，普通请求按全局、国家的固定顺序取共享锁，相关管理动作在对应层取排他锁。收权完成返回后，旧授权不得再提交新写入；命令提交前再次校验有效期，过期则整体回滚。
- `sys_user_data_scope` API 保留 scopeType/scopeRefId；DB 用受类型 CHECK 限制的 entity/store/warehouse/book 具体 FK 列，避免裸多态 ID 跨国。
- 国家 RLS 上下文仅在当前事务、同一连接用 `set_config(...,true)` 设置，缺失时拒绝；请求 finally 清理内存上下文，禁止连接级 SET 污染连接池。普通 GET、分页/count、附件元数据查询及 worker 读取都由显式 QueryService 事务覆盖，在首次业务 SQL 前设置上下文；查询保持无业务写入，但 PostgreSQL `READ ONLY` 事务禁止授权闸门所需的 `FOR SHARE`，因此这些事务不设置 JDBC/Spring `readOnly=true`。数据库流式游标覆盖完整事务/连接生命周期，禁止仅在请求过滤器的临时连接上设置。全局用户表仍有独立管理范围，不因无 country_id 公开。
- DTO 显式标注 COST/CUSTOMER_PRICE/ORDER_TOTAL/BANK_INFO/PROFIT/CREDIT，输入检查 WRITE、输出检查 READ；导出也用同策略，毛利等派生字段同步控制，不能由两个可见字段还原隐藏成本。
- 附件执行时校验本单、国家、类别、有效对象、链接版本和 hash；附件解绑与关键动作争用同一源单锁。对象上传在事务外，完成后才登记有效元数据，临时孤儿清理不删业务凭据。
- 导出/AI/缓存快照保存来源引用、发起人和策略版本，执行、读取与下载重新验证；旧 AI 文本不直接返回，收权后丢弃或重新生成。AI 外部调用不持事务，返回后重验授权，模型没有业务写工具。

原文档 5 分钟签名 URL 存在“撤权后仍可用至到期”的窗口。敏感成本/银行/付款凭据推荐经授权下载代理逐次校验；如选择签名 URL，必须明确接受有效期内的撤权延迟，不宣称立即失效。此项为安全实现方式细化，不改变附件归属规则。

## 11. 真实 PostgreSQL 验收场景

以下为 24 组跨阶段场景要求；M0–M3 已执行范围见各阶段验收记录，结账与切换场景仍待所属阶段实施；涉及竞争的场景需要独立连接/请求线程和同步屏障，不能用串行 Promise、H2 或内存 Mock 代替竞争条件。

1. 结账与出库互争闸门：业务先锁则全部提交后结账再查；关闭先完成则业务整体拒绝，无库存/应收/事件残留。
2. 两个账套独立结账；反结账时后续已结期间拒绝，后续开放依赖可追溯，旧豁免失效，新旧快照并存。
3. 同一来源事件多消费者、重复投递/不同 key 生成和同凭证并发记账：一张凭证、一次余额增量；杀 worker 后可恢复。
4. 部分分录、批次变动或来源余额后注入异常：事实完全回滚，独立失败诊断存在且不会覆盖后来成功。
5. 最后 10 件库存，两个订单各预留或出库 6/7 件：不超用，失败方没有应收、信用和流水半成品。
6. 预留/冻结/调拨同时竞争同 SKU，反向输入多 SKU：汇总、批次、预留守恒，死锁重试不重复效果。
7. 盘点开始与出入库并发：变动在快照前完成或被持久盘点锁拒绝，不遗漏快照后的变动。
8. 同境外实收并发 20 次，相同 key 和不同 key：只一批库存/成本/事件；同 key 改内容 409。
9. 调拨在途 10 并发各收 6；历史分配仅 2 却请求 10：累计不超量、异常全回滚。
10. 国内退供/出口、发运/暂缓/派送争同来源，含重复来源行：各桶非负、总量守恒，两个阶段退货不混扣。
11. 授信 1000 并发两单各 700；本单预占转应收；超额/逾期无规则：不超占、不重复、不能免审。
12. 收款 100 并发核销各 70、撤销重复请求、挪用别单预收：两侧余额、信用、订单分配一致。
13. 采购来源 100 并发开应付各 60、同物流费并发建账单、伪造原价：规范化来源和原子上限生效，作废才释放。
14. AP 付款/预付/贷项及应付两侧竞争；结算后修改汇率并撤销：历史快照与真实汇差不变。
15. 实交 10 并发申请退货各 6；重复验货/结算：申请上限、实际入库、原价和贷项用途守恒。
16. 可退款 100 并发申请各 60、退款与核销竞争、支付与附件解绑竞争：不超用，有效证据缺失拒付，重复支付只登记一次。
17. 暂估 100→实际 150，10 件已售 4：差额库存 30、COGS 20；缺率恢复、两个实际费用及重复确认不能重复资本化。
18. 同 SKU 多行多批次移动平均，晚补成本、后到费用、已退回再出售：使用冻结计价池，净已售和在库正确。
19. 四位数量、八位汇率、多币种尾差：逐行舍入且本位币分摊严格守恒；原币不直接相加，零差额按复核策略处理。
20. 多客户/供应商/账户/币种及上期余额：试算、明细、总账一致，采购/运费/应付转正式不重复入账。
21. 直接 SQL 跨国/账套引用、缺国家上下文、修改已记账分录/成本事实、改审计：FK/RLS/不可变约束拒绝；连接池切换及异常后不串国。
22. 两实例缓存旧权限，第三请求收权/授权到期：后续 API、旧报表、导出执行/下载、AI 历史、附件和幂等重放均重新校验。
23. 分仓订单及全部来源链：列表、详情、计数、汇总、来源下钻和所有写响应一致隐藏他仓数据及敏感字段；管理员不得扩大权限、范围或期限。
24. 空库迁移/升级、历史异常隔离、重跑迁移批次、备份及对象恢复、Mock 关闭后两个国家完整页面主流程。

拟执行命令：`cd jxc-server && ./mvnw verify -Ppg-it`；现有 `cd jxc-web && npm test && npm run build`。命令、profile 与测试类在 M1 建立后运行；后端测试未运行不能写“通过”。性能按约定数据量另做 p95/锁等待/慢 SQL/消费者积压验证，当前未提供业务规模，不虚构容量结论。

## 12. 兼容退出、清理及验收报告要求

当前 `mock/browser.ts`、`scenario.ts`、Node 测试及离线演示仍调用 Mock，保留至真实服务端通过契约、上述 PG 验收和原页面验收。生产构建必须关闭 Mock，启动时检查配置并拒绝自动回退；离线演示可保留明确独立入口，禁止双写。

正式服务只使用 PostgreSQL，不调用 `snapshotDb/restoreDb`、GET 扫描补事件、浏览器权威成本或 localStorage。迁移时同次清理被替换的生产入口和重复算法；Mock 测试替身仍有调用时不删除。只有全部调用迁移且确认不再提供离线演示，才删除对应 Mock 文件与不再承担独立约束的测试。

旧出库快照缺失、旧缓存没有来源引用的兼容只服务核验中的历史数据；待每条有效记录具备可核验来源/快照或正式归档后才移除。没有确定迁移日期，不承诺自动修复历史事实。

每阶段报告新增/修改/删除、共享能力调用点及重复逻辑清理；分别统计业务、测试、文档/配置和生成物，区分独立测试契约与参数展开，分别记录单元、真实 PG、并发、构建、部署及浏览器结果。不得把 Mock 通过、CI 通过或首页 200 当作真实业务验收。

本方案初稿阶段仅产出方案与总览；后续经用户授权实施的 M0–M5 已新增真实后端、迁移、运维工具和测试，具体变更及实际验证以独立验收记录为准。剩余生产配置包括人员/审批、账套归属、科目及事件映射、汇率/期初/计价方法、实际历史迁移范围、恢复目标和性能基线。

## 13. 核实的技术依据

- [PostgreSQL 行锁与统一锁序](https://www.postgresql.org/docs/current/explicit-locking.html)：用于共享/排他闸门设计。
- [PostgreSQL 约束](https://www.postgresql.org/docs/current/ddl-constraints.html)：CHECK 不承担跨表累计约束，使用唯一/FK/排斥及明确锁点。
- [PostgreSQL 约束触发器](https://www.postgresql.org/docs/current/sql-createtrigger.html)：用于提交时复核表头/分录一致性。
- [PostgreSQL RLS](https://www.postgresql.org/docs/current/ddl-rowsecurity.html)：国家兜底需结合非 owner、无 BYPASSRLS 的运行身份；不能替代来源权限。
- [Spring 事务绑定事件](https://docs.spring.io/spring-framework/reference/data-access/transaction/event.html)：事务阶段回调不等于持久消息队列，本方案以原事件表保证崩溃后可恢复。
