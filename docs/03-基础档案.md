# 03 基础档案

## 1. 模块目标与来源

- PRD 来源：第 03 章（基础档案；商品与业务数据的共享范围）、第 17 章（币种汇率）。
- 目标：维护以下档案，供所有业务模块引用：
  - 商品、条码、规格、单位换算；
  - 客户及地址、销售归属；
  - 供应商、物流商及结算信息；
  - 费用项目、币种、汇率、银行与现金账户、业务字典。

会计科目由 [12 内部财务](12-内部财务总账与结账.md) 维护，客户价格由 [07 销售](07-销售与门店.md) 维护，授信规则由 [08](08-收款授信与客户应收.md) 维护。

## 2. 范围

| 一期做 | 一期不做 |
| --- | --- |
| 全局商品主档；各国自行启用经营 SKU | 商品图片管理、电商详情页 |
| 客户、供应商、物流商档案，按国家独立 | 客户自助注册 |
| 费用项目，以及计入成本或期间费用的默认处理方式 | 营销费用项目 |
| 手工维护并确认汇率 | 自动从外部拉取汇率 |
| 银行与现金账户（只登记，不对接银行） | 银行流水自动导入 |

## 4. 共享与隔离规则

| 档案 | 归属 | 说明 |
| --- | --- | --- |
| 商品编码、名称、规格、条码、基础单位、单位换算 | 全局共享 | 被授权的国家可以引用 |
| 经营 SKU 启用、本地名称、税类 | 按国家 | 各国自行启用，同一商品在不同国家可以有不同的价格、成本、阈值 |
| 客户、供应商、物流商的业务关系 | 按国家 | 复制国家时不复制 |
| 费用项目、字典 | 按国家 | 模板复制时可复制结构 |
| 汇率 | 按国家 | 每个国家独立维护和确认 |
| 银行与现金账户 | 按国家与主体 | 复制国家时不复制 |

## 5. 业务规则

### 5.1 商品与单位

- `product_code` 全局唯一；条码全局唯一（同一条码不能对应两个商品或单位）。
- 每个商品有一个基础单位，其他单位（箱、包）配置换算系数 `factor_to_base`（例如 1 箱 = 24 件）。
- 业务单据保存录入单位、录入数量和基础单位数量 `base_qty`；库存与统计一律使用 `base_qty`（PRD 第 07 章要求不能混加箱数与件数）。
- 换算系数被历史单据引用后不能修改，只能新增单位或停用旧单位。

### 5.2 客户

- 客户属于国家，字段包括客户组、客户等级、销售归属（业务员）、归属门店。
- 地址字段按国家的 `address_rule` 校验。
- 客户的赊销资格、额度、账期不放在客户档案里，统一在授信规则中配置。

### 5.3 供应商与物流商

- 档案类型 `partner_type`：SUPPLIER（供应商）、LOGISTICS（物流商）、BOTH（两者兼有）。
- 结算信息：默认结算币种、付款条件、银行信息（加密存储，脱敏显示）。
- 物流商复用同一套往来与对账能力（见 [09](09-供应商物流商应付.md)）。

### 5.4 费用项目

| 字段 | 说明 |
| --- | --- |
| `fee_category` | FREIGHT_SEA / FREIGHT_AIR / CUSTOMS / TRANSSHIP / DELIVERY / DEMURRAGE / STORAGE / OTHER |
| `cost_treatment` | CAPITALIZE（计入商品成本）/ PERIOD_EXPENSE（期间费用）/ DIRECT_SELLING（直接销售费用） |
| `default_alloc_basis` | QTY / WEIGHT / VOLUME / VALUE / MANUAL |
| `account_id` | 默认科目，由财务配置 |

不设置营销费用类别（PRD 第 02 章、D09）。

### 5.5 汇率

- 每条汇率包括：原币、目标币、汇率值、汇率日期、适用范围（PURCHASE_COST / SETTLEMENT / REPORT / ALL）、版本、状态。
- 状态流转：`DRAFT`（录入）到 `CONFIRMED`（授权人员确认）；被新版本替代后为 `RETIRED`。只有 CONFIRMED 的汇率能用于成本确认和记账。
- 取值规则：同一适用范围内，取汇率日期不晚于业务日期的最近一条已确认汇率；没有时返回“待补汇率”。
- 修改汇率时生成新版本，已确认的单据不重算（对应 A21）。

### 5.6 银行与现金账户

- 账户类型：CASH（现金）、BANK（银行）。字段包括币种、所属主体、所属门店（可空）、对应科目（12 中配置）。
- 门店可以有独立的收款账户（PRD 第 09 章）。

### 5.7 停用而非删除

所有档案被历史单据引用后只能停用。删除接口会检查引用关系，有引用时返回 `MD_REFERENCED`。

## 6. 状态

档案状态：`ENABLED`（启用）、`DISABLED`（停用）。汇率状态：`DRAFT`、`CONFIRMED`、`RETIRED`。

## 7. 数据模型

### 7.1 商品

| 表 | 关键字段 |
| --- | --- |
| `md_category`（全局） | `code`、`name`、`parent_id`、`level` |
| `md_product`（全局） | `product_code` 唯一、`name`、`name_i18n jsonb`、`category_id`、`brand`、`spec`、`model`、`base_unit`、`gross_weight`、`volume`、`hs_code`、`status` |
| `md_product_unit`（全局） | `product_id`、`unit`、`factor_to_base numeric(18,6)`、`is_purchase_default`、`is_sales_default`、`status`；`(product_id, unit)` 唯一 |
| `md_product_barcode`（全局） | `barcode` 唯一、`product_id`、`unit` |
| `md_country_sku` | `country_id`、`product_id`、`local_name`、`tax_category`、`status`；`(country_id, product_id)` 唯一 |

### 7.2 客户

| 表 | 关键字段 |
| --- | --- |
| `md_customer_group` | `code`、`name` |
| `md_customer_level` | `code`、`name`、`seq` |
| `md_customer` | `code`、`name`、`customer_type`（COMPANY/PERSON）、`group_id`、`level_id`、`tax_id`、`phone`、`email`、`sales_owner_id`、`store_id`、`status`；`(country_id, code)` 唯一 |
| `md_customer_address` | `customer_id`、`contact_name`、`contact_phone`、`address jsonb`、`is_default` |

### 7.3 供应商与物流商

| 表 | 关键字段 |
| --- | --- |
| `md_partner` | `code`、`name`、`partner_type`、`located_country`、`contact`、`phone`、`settle_currency`、`payment_terms`、`status`；`(country_id, code)` 唯一 |
| `md_partner_bank` | `partner_id`、`bank_name`、`account_name`、`account_no_enc`、`account_no_masked`、`swift`、`currency`、`is_default` |

### 7.4 费用、币种、汇率、账户、字典

| 表 | 关键字段 |
| --- | --- |
| `md_expense_item` | `code`、`name`、`fee_category`、`cost_treatment`、`default_alloc_basis`、`account_id`、`status` |
| `md_currency`（全局） | `code` 主键、`name`、`symbol`、`decimals` |
| `md_exchange_rate` | `from_ccy`、`to_ccy`、`rate numeric(18,8)`、`rate_date`、`scope`、`version_no`、`status`、`confirmed_by`、`confirmed_at`；`(country_id, from_ccy, to_ccy, rate_date, scope, version_no)` 唯一 |
| `md_fund_account` | `entity_id`、`store_id`、`account_type`、`currency`、`name`、`bank_name`、`account_no_enc`、`account_no_masked`、`gl_account_id`、`status` |
| `md_dict` | `country_id`（可空，为空表示全局）、`dict_type`、`code`、`label_i18n jsonb`、`seq`、`status` |

一期内置的字典类型：

- `SALES_SOURCE`：业务员、门店；
- `RETURN_REASON`：退货原因；
- `HOLD_REASON`：暂缓派送原因；
- `DISCREPANCY_REASON`：到货差异原因；
- `RESPONSIBILITY`：责任方。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| CRUD | `/api/v1/md/categories` | 商品分类 |

| CRUD | `/api/v1/md/partners` | 供应商与物流商 |
| GET | `/api/v1/md/partners/{id}/banks` | 银行信息，需要 `md:partner:bank-view` |
| CRUD | `/api/v1/md/expense-items` | 费用项目 |
| GET | `/api/v1/md/currencies` | 币种 |
| CRUD | `/api/v1/md/exchange-rates` | 汇率录入 |
| POST | `/api/v1/md/exchange-rates/{id}/confirm` | 汇率确认 |
| GET | `/api/v1/md/exchange-rates/resolve?from=&to=&date=&scope=` | 查询适用汇率 |

- `ProductApi.toBaseQty(productId, unit, qty)`：单位换算；
- `RateApi.resolve(...)`：查询适用汇率，没有时返回空并带原因；
- `CustomerApi`、`PartnerApi`：返回档案快照。

## 10. 跨模块依赖

- 被 04 至 12 所有业务模块引用。
- 汇率被 09（结算换算）、11（入库成本）、12（记账本位币）使用。
- 费用项目的 `cost_treatment` 决定 11 中的分摊处理方式。

## 11. 对应验收用例

A21（汇率确认与版本，缺汇率时拦截）、A35（各国使用本国币种和汇率）、A36（档案业务关系按国家独立）。

## 12. 待确认与实施配置

- 商品分类体系和编码规则。
- 汇率维护频率（每日或每次结算）和适用范围的划分。
- 税类（`tax_category`）的取值，由各国财务确定。
