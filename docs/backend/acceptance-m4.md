> 状态：已完成 M4 实施与隔离验收（2026-10-16）。最终完整后端 333/333、前端 143/143、生产构建及契约检查通过；双国真实登录、财务命令、来源页面、权限和实际下载已验。M0–M3 历史证据保留；M5 迁移与生产切换未执行。

本轮沿用既有接口、业务规则与原 Vue 页面，复用 M1 当前授权、账套与期间闸门、UUID 幂等、审计、私有附件及事务事件消费者。财务报表以已记账分录与已确认期初为来源；业务利润复用采购、成本、销售、费用和退货所属模块的只读事实接口，不新增平行成本或总账，不通过 GET 自动补造映射、科目、期初、凭证或业务单据。

## 结账与反结账

结账在账套排他闸门内重新读取当前期间、未完成业务与事件、成本完整性、待审/未记账凭证、试算及往来/库存/现金核对，不依赖之前页面上的检查结果。存在待处理事件时返回来源详情并释放闸门，不能持排他锁等待异步消费者。结构性缺项不可豁免；差异确认绑定完整来源指纹与候选结账代次，来源变化或反结账后须重新核对。默认差异容限为零，没有沿用演示环境的隐含容差。

通过检查后，在同一事务内追加 BALANCE、REPORT、RECONCILE 三类不可变快照、关闭当期并开放下期。快照键为期间、代次、类型；同一意图重放不产生新代次。自然月期间可按现有规则建立紧接的自然月；其他期间必须先明确配置连续的下一期间，不能自行猜测。下期余额沿已有已确认事实结转，不补造未知期初。

反结账检查独立权限、原因与后续期间依赖；存在后续已结期间时拒绝，后续开放期间的影响可追溯。旧代次保持只读，旧差异确认失效，再次结账生成新代次。对 CLOSED 期间执行检查不改变状态。

数据库约束保证快照不可变、结构完整、结账代次合法，以及余额/分录与已记账事实一致。财务报表的受控公式由服务端 `ReportApi` 统一计算；数据库信任这一服务端算法的派生结果，不声称在 SQL 中重新验算每个报表金额，也不复制跨模块公式。运行角色不能直接改写快照、代次或已记账事实。

## 报表、业务利润与授权导出

资产负债表和利润表使用操作者显式创建、复核的模板；表达式只支持登记的受控语法，不执行任意脚本。现金流量表沿实际现金/银行分录和明确现金流项目。配置缺失明确返回不可用及缺项，不静默创建模板。开放期复合读取使用同一数据库事务快照；已结期间报表、账簿和核对读取相应冻结代次，读取时仍重新检查当前功能、字段与数据权限。

业务利润与正式财务利润表分别展示：业务利润保留原四位成本、冻结汇率、费用归集及退货/冲销来源，显示完整度、来源版本和核对差异。缺成本或冻结汇率时金额保持未知，不用零替代。没有独立权威税额的销售事实不能根据可变税率反推税款。AI 提供商尚未配置时受控提示不可用，不伪造模型输出或历史分析。

报表导出复用事务 outbox、消费租约和失败诊断。结果与通知在同一成功事务提交；失败不留下半份文件或成功通知，并可重试原任务。技术导出事件不构成财务事件，不要求伪造一个开放会计期间。执行、任务读取、下载及幂等重放均重新检查当前发起人授权；导出只向原发起人开放，并按现有时效控制。CSV 文本做公式注入防护，数值保持数值口径。工作台 GET 只读取已有待办、通知和模块事实，不在读取时重建业务任务或事件。

## 真实前端与兼容退出

默认开发和生产构建连接真实后端；Mock 仅由明确独立的演示模式启用。真实模式清理本应用残留的 Mock Service Worker 接管，不删除浏览器既有业务缓存数据，也不在真实接口失败后回退模拟写入。原 Vue 页面继续使用现有指令意图及 UUID 重试规则；切换国家后旧响应和旧排队命令不能串入新国家。

原结账、报表、试算、账簿、业务利润和导出任务页面补齐明确账套/期间、来源指纹/快照代次、缺项与差异、当前币种及国家时区。采购进度复用 PUR 与 LGS 所属模块的只读接口，按当前采购订单过滤混单出口、货运与收货行，历史 SKU 停用不使已发生事实消失，采购金额继续按当前字段权限脱敏；没有让前端自行跨模块拼出全量业务表。

Mock 原五个业务回归文件继续保留为演示和规则回归；是否删除模拟写流程须另以 M5 历史迁移、受控切换及目标环境验收为依据。本轮真实页面验收使用隔离合成数据，不等于生产切换。

## 复用与回归修复

- FIN 新增结账、反结账、快照、报表模板与正式报表服务；修改原账簿与核对读取入口以复用冻结代次，并将技术导出事件排除在待生成凭证与结账财务事件检查之外。没有新增第二套总账事实。
- CST 业务利润沿 SAL、RTN、成本和费用所属模块事实接口读取，保留后到费用、退货结算/撤销日期及成本完整度。利润专用角色可选择授权账套，不能因此获得期间管理权限。
- SYS 导出复用原事务事件消费者，新增同一效果事务的 REPEATABLE READ 入口、持久任务结果和成功通知。重启后恢复只处理已提交的技术任务，每次使用原提交会话重新授权，不创建服务管理员或借用复核人身份。
- 工作台继续读取现有审批与配置缺失待办；修复原审批列表超过 200 条时摘要和后续分页遗漏，以及历史个人待办在数据范围被收回后继续暴露的问题。GET 不补建任务。
- 修复结账前后冻结来源读取、NOT_STARTED 期间不能结账、独立反结账权限、SQL 快照空值/伪造可用标记、下期真实余额依赖等边界。结账 SQL 保持结构与真实余额校验，派生报表公式仍统一由服务端计算。
- 技术导出例外保持为准确的事件/来源类型组合；金融事件仍受原期间锁和不可变约束，并保留已有的错误诊断契约。导出提交后执行器未接手的任务可恢复，失败不会留下成功文件或通知。
- 原 `AuditTimeline` 的 `/sys/audit-logs` 已沿现有审计事实接通，复用来源所属模块权限、数据范围与当前字段策略；查询不补写审计或业务事件，凭据/密文递归剔除。审计查询 4 项实际 PG 回归已纳入最终完整后端验证；页面操作另以浏览器清单计证。
- 原采购、物流、销售与退货页面补齐真实 DTO 的来源名称与进度字段。商品复用 `MasterProductApi.reference`；客户/供应商/承运商/费用项目只经所属模块的最窄名称引用，用户/主体/门店/仓库经 SYS 组织引用。调用前先授权原业务来源，只返回所需标签，停用档案仍可解释历史事实；没有新增跨模块业务 SQL 或 MD 管理权限，名称引用复用原所属模块查询逻辑。
- 销售订单、行与分仓的 `openQty` 复用原基础数量减已取消减已出库的规则，在当前行/分仓范围裁剪完成后统一计算，再应用现行金额字段遮罩。分仓角色显示自己的未出库数量，不带出全订单总量。物流新增 `ShipmentPresentationIT` 两项 PG 用例；采购进度继续扩展原两项用例，销售、退货和审批展示扩展已有 `SalesIT`、`ReturnsRefundsIT`、`WorkflowIT` 方法，没有复制独立测试方法来增加计数。

- 共享选项沿原 Pinia store 修复 `size=500` 超过真实接口最大 200 的问题，逐页取全且调用方不能覆盖分页参数；国家、登录及缓存 generation 在每页前后与写缓存前用同一个校验。独立审阅补出 A→B→A 旧分页继续的问题，扩原用例验证。浏览器再发现 Pinia devtools 为每次 action 建新 Proxy，导致原 `WeakMap(this)` 反复清缓存；以 `toRaw(this.$state)` 为稳定身份修复，新增真实 Vue watcher 与相同 action Proxy 边界测试，修前重跑 21 次、修后稳定。没有关闭开发工具或隐藏错误。
- 契约生成器沿原 AST 请求提取支持本文件受控 `allRecords` GET 包装，保留明确字典 GET 证据；扩原契约断言，未知动态调用仍待审阅。真实页面的账套选择器给予明确宽度，所选账套名称与期间同时可读。
