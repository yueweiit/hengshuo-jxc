2026-10-15，按已批准方案完成 M0/M1。原工作区没有 Git HEAD，原文件均未跟踪；没有执行提交、重置、删除或生产迁移。变更统计以本轮开始前保存的 docs、前端源码/测试快照为基线，新建后端按新增计算。

## 实际交付

- M0 契约：459 条 MSW 注册、437 个 method/path；保留 22 条覆盖关系，56 个只读资源隐藏写入口明确 blocked。冻结原 101 个 test 调用点、111 个展开用例和 7 个共享 HTTP 场景。真实 M1 的 64 个 Controller 映射使用 47 个复用 schema，明确请求、响应、错误、权限/范围/字段、幂等和实现证据；后续未开放接口保留 unknown/deferred，不把扫描结果当成服务端实现。
- 后端：Java 21 编译目标、Spring Boot 4.1.1、MyBatis-Plus 3.5.17、Flyway、PostgreSQL 16、MinIO SDK 9.0.3。拆分 common、sys、fin、app；普通查询和命令均在同一事务/连接设置国家上下文，查询不写业务数据。
- V001/V002：组织与币种/基础账户、真实会话、角色/范围/字段授权、全局及国家授权闸门、账套期间、幂等、outbox/消费记录、追加审计、附件、最小审批和待办。21 张国家业务表 FORCE RLS，授权闸门另含全局哨兵策略；复合 FK 和安全整数域阻断跨国/跨账套引用。
- 权限：BCrypt、仅保存 token 摘要、过期/撤销；先拿授权闸门再读取权威权限。角色/用户授权遵守自身功能、字段、范围和期限上界，4 个授权替换 PUT 使用 version CAS。组织归属变更从入口取得国家排他授权闸门，避免派生范围在等待行锁后过时。
- 期间：统一 PeriodApi/BookGate；业务共享账套锁、配置排他锁，禁止共享升级。DB 守卫先锁账套再判业务日期所属开放期间；生成年度期间不会重开既有 CLOSED 月份，并在等待排他锁后重验账套状态。没有开放实际结账/反结账路由。
- 幂等：UUID key 与国家、用户、method、规范化路径、可信账套和规范化请求体绑定；占位、业务、结果同事务。失败整体回滚，相同 key 并发只有一个效果；重放重新授权并按当前字段策略输出。
- outbox：同业务事务发布、来源唯一；worker 基础提供短租约领取、独立效果事务、消费唯一及版本 CAS。效果回滚后另开短事务保存脱敏失败诊断，旧失败不能覆盖新成功。M1 没有注册财务或成本业务消费者，也没有 GET 补事件/重算路径。
- 审批：沿用规则条件、规则版本、关键字段快照和现有权限码；必需审批没有有效规则/审批人时 BLOCKED 并生成待办。未登记的 M2 来源默认拒绝。
- 附件：私有 MinIO 对象、数据库元数据/链接、来源锁、哈希/类别/链接版本复核；下载代理每次重验当前会话、来源及字段权限。PreparedEvidence 将事务外对象 I/O 与调用方事务内锁定复核分开，复用同一验证实现。
- 初始化：单独 bootstrap profile 和显式脚本，仅接受操作者所有的 regular 0600 JSON，校验准确数据库名和空库，具体权限/全部字段策略显式提供。密码 BCrypt，配置写入与脱敏审计同一事务；不生成演示账号、库存、期间、凭证、期初或审批人。
- 前端：复用 postIdem 和通用 CRUD；同意图失败保留 key，成功/改内容/换会话国家/重开意图换 key，合并在途双击，不自动重试财务 POST。保留 PUT version；授权两步替换衔接新版本；新用户必须显式安全密码；附件同源授权 blob 下载。尚未开放的 M2 表单适配不等于业务事务已实现。

## 保留边界与技术债

- M2 库存/采购物流/销售/往来/退货及其最小成本事实、M3 成本/总账、M4 结账/报表/全界面、M5 历史迁移和上线仍按原方案实施。本次未部署生产，未迁历史或建立真实财务配置；未做原 Vue 双国主流程浏览器验收、CI 或性能基线。
- M1 真实基础路由已定义 DTO/策略；其余尚未开放接口的完整 DTO 与来源条件仍待所属阶段复核。账套/币种/国家首次配置来自显式 bootstrap；国家复制向导、完整资金账户维护和报表等路由尚未开放。
- 附件当前仅允许 M1 基础来源的 IMPORT_FILE，大小 1MB，内容不透明故要求全部字段组权限。M2 需随可信业务来源登记既有凭据类别。私有孤儿对象清理未自动化；生产对象服务及镜像升级另行选定，当前固定的 2024 MinIO 摘要仅是隔离测试证据。
- md_fund_account 的 gl_account_id 仅保留安全整数及账套归属约束，M3 科目表建立时补复合 FK；当前查询绝不输出加密账号列。事件消费者业务注册与最终事件汇总状态随 M2/M3 实现，M1 只有可靠执行基础。
- 审批首次单据类型配置可通过既有 PUT API 创建，现有设置页缺少首次新增入口；不自动填入审批配置来掩盖缺项。具体人员、审批、科目/映射、期初、汇率及计价方法仍需业务确认。
- Mock 保留用于原演示、回归和实现对照；M4 双国真实界面验收、生产关闭 Mock 且所有调用迁移后，再清理生产接管和失效兼容。显式真实模式没有失败后切回 Mock 或双写。
