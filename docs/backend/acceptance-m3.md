# M3 真实成本与内部总账验收

本轮沿用既有 `/cst`、`/fin` 及业务单据接口，复用 M1 授权、账套/期间闸门、UUID 幂等、审批、私有附件、审计及事务事件。采购物流、库存、销售往来和退货退款仍由 M2 所属模块维护；FIN 通过模块公开的只读来源接口取数，不反向修改业务单据，也不直接查询其他模块的业务表。M0–M2 的验收记录保留为历史证据。

计数、命令退出码及分类变更以 `evidence/verification-m3.json`、`evidence/change-statistics-m3.json` 为准。聚焦测试通过不代表全量通过，接口通过不代表登录后的浏览器验收。

## 成本

- 复用原采购价格、数量、单位换算、成本方法和已确认汇率事实；确认以追加记录补齐缺项。已完整入库成本、原出库成本及原调拨快照不覆盖，缺来源/缺汇率继续明确 PENDING，不能用零或当前汇率代替。
- 分摊支持原数量、价值、重量、体积及人工规则。按币种精度和稳定顺序吸收尾差，总额守恒；人工分摊与人工调整沿用原审批机制。不存在有效审批规则时不得通过确认绕过。
- 后到费用、实际替换暂估、分摊冲销和退回后的费用贡献以追加差额处理。FIFO 沿批次贡献，移动平均沿冻结池数量传播；库存、已售及在途贡献保持总额守恒。实际替换仅确认与原冻结暂估之间的差额。
- 原四位成本事实和账簿币种精度分开保存。记账金额沿不可变的成本确认顺序累计吸收尾差，采购、费用、销售、退货和库存来源共用同一分配接口；总成本 1 元分三次出库仍完整结转 1 元，不逐行独立舍入丢失分位。
- 期间费用和直接销售费用保留原币、本位币、冻结汇率及分配事实，资本化项目不能借费用登记入口绕过分摊。
- 未分摊的资本化费用仍为业务资产，并明确显示待分摊。已分摊本金由原费用确认事件负责，成本重分类事件只在库存和销售成本之间转移已售份额，防止再次增加应付。

## 映射、凭证与账簿

- 映射编辑生成待复核版本，复核后不可改写；修改必须建立新版本。金额表达式只能引用登记的金额字段，不执行任意脚本。科目可复用原固定科目、资金账户、费用项目和分类配置，逐一校验国家、账套、末级/启用状态及辅助项。
- 业务事件来自现有不可变 outbox；GET 事件列表与余额核对不扫描业务表重建事件。生成复用 M1 消费租约、失败诊断和重试，事件解释与待审凭证、分录、幂等、审计在同一事务中提交。失败仅保留受控诊断，不留半张凭证或成功幂等记录。
- 生成只产生待审凭证；编审分离，审核通过后才可记账。已记账分录是唯一总账事实，余额表只是可校验的投影，运行角色不能伪造余额或修改已记账事实。重复维度先合并，多个凭证并发更新余额不丢失。
- 冲销追加待审红字凭证，继续审核和记账；原凭证、原分录保留。未完成冲销不能再生成第二张冲销。已确认期初必须明确录入、试算平衡、显式确认；GET 不确认期初，凭证日期不得覆盖已确认期初截止范围。
- AR 核销和 AP 结算不能再次确认现金银行；退货结算的贷项兑现不能重复确认收入。采购退货由退货事件统一解释库存成本及冻结应付贷项，贷项创建只提供来源确认。原始核销、冲销均保留符号和原冻结转换；分次结算累计吸收本位币记账精度尾差，冲销精确取反原分配。
- 采购成本和资本化费用分别提供原单应付本金、固定库存记账金额及其精度差额。暂估转实际的应付变化取“新本金舍入后减原本金舍入后”，不能先对原四位净差舍入。映射引用现有受控字段将差额计入操作者明确配置的差额科目；生成分录包含应付核对科目时，服务端校验应付净变化必须等于冻结本金，不能仅凭借贷平衡放行少确认应付的凭证。沿用明确暂估科目的配置时，未开单差异仍如实保留。
- M2 销售出库只有权威成交金额，没有独立确认税额。M3 沿用原会计来源口径，不根据可变税率补造应收、税款或税务凭证。涉及原币但缺少实际冻结本位币换算的来源明确失败待补，不自动按当前汇率重估。

## 核对与权限

AR、AP、库存和现金业务余额独立于已记账总账取数。AP 业务口径沿用 M2 的已确认账单余额；若已复核入库映射直接贷应付，而应付账单尚未建立，核对会如实显示未开单差异。测试覆盖该差异，不自动建立账单、凭证或未知期初清差；暂估/正式应付科目及其转换须由操作者按实际规则复核配置。核对按明确期间截止日读取，分开呈现业务余额、总账余额、未生成、未记账、待成本/待汇率/待分摊及可追溯来源。缺项时差额为未完整，不把未知金额当零。核对和账簿复合读使用一致事务快照，避免并发提交导致同一次返回混入不同时间的数据。

库存核对保留原业务估值金额及差额，额外列出来源事实的固定记账金额、记账精度分配差额、扣除该精度差额后仍待核对的金额，并保留逐笔原金额和分配金额。跨期补录可使按截止日汇总后舍入的估值与此前固定的分位分配相差一分；该差异明确展示，不重排已解释来源，不生成无业务依据的跨期调账凭证，也不将原业务差额改为零。

每次命令及幂等重放重新检查当前会话、功能、字段与数据范围；权限被撤销后不能凭旧成功结果继续读金额或流转状态。跨国家、跨账套和错误辅助项引用在服务与数据库约束中拒绝。审核、记账、冲销需要当前可读金额，配置和人工输入遵守既有写权限。

后台自动生成默认关闭。启用时必须显式指定现存国家/操作者，逐次重新验证其当前授权；不创建管理员、不借用模板复核人身份，也不自动授予权限或范围。后台只生成待审凭证，不自动审核或记账。

## 验证与边界

验证在隔离的 PostgreSQL 16 / MinIO Testcontainers 中运行，使用合成测试国家、人员、配置与业务单据；未对已有业务库写入，没有真实期初、真实过账、外部支付或生产部署。

重点覆盖并发分摊、重复生成、同意图重放、并发记账、来源缺项恢复、实际替换、退回/在途成本、红字冲销、失败后完整回滚、权限降级和读取快照。既有 M2 业务链扩展验证实际事件到待审凭证、另一用户审核、记账及来源与总账核对，避免用测试自建算法替代服务。

M4 尚未实施：结账/反结账、结账快照、正式财务报表、数据迁移及完整真实页面切换。现有 Mock 保留作为演示与原规则回归；新增真实配置在 Mock 无相同能力时明确隐藏，没有增建平行 Mock 财务后端。完整退出须以受控真实配置、目标环境登录后的全业务页面验收及数据迁移结果为条件。
