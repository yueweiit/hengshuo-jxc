# 库存、销售需求、业务待办与统一导入闭环

范围：INV、PUR/LGS 期初来源、SAL 统计／价格、AR 期初与导出、RTN 待办及 SYS 导入编排。本文说明公开代码能力和验证方法；现场单据、金额、余额、截图和私有执行目录均保存在非公开位置。源码与制品绑定见 [发布清单](../releases/2026-10-20-source-binding.json)。

## 统一导入与原生期初

`ImportHandler`／`ImportService`／`ImportController` 仅编排原归属命令，模板来自实际注册且当前用户有权限的处理器。服务端计算文件 hash，保存不可变批次、来源标识和目标映射，确认使用同一事务；预校验／取消不登记库存、单位使用或来源占用。

价格、授信、上下限、库存、AR／预收、未完采购与在途均有明确处理器；MD 主档及 FIN/AP 期初由所属模块处理。导入界面支持 UTF-8 JSON 文件和 JSON 文本，不宣称支持 Excel 二进制解析。

- `InventoryApi.opening` 复用批次、成本快照及估值池，形成原生 `OPENING_IN`；成本未知拒绝，不伪造采购实收。
- AR 期初为原生应收，预收为可核销 `OPENING_ADVANCE` 贷项，均保留来源、截止日和导入外键；无虚构销售、银行收款或付款。
- 未完采购保留原生 DRAFT，正常审批后才可被同截止日期在途引用。`OPENING_PURCHASE_LINE` 沿用 PUR 来源锁及数量命令，后续到港、换柜、派送和实收复用原物流／库存服务。
- `opening_shipped_qty` 单独占用历史已发运量，后续国内收货、取消和未交不能重复使用。截止日与普通业务期间分别校验，普通交易不能冒用期初通道。
- 只有经过服务端校验的 `ImportScope`／`OpeningOrigin` 能建立受控来源，批次、行、目标和经济快照均须相符；来源经济字段不可改，后续原生状态投影仅允许明确白名单。
- 子账和总账分别录入、独立核对；缺失、null 与明确零区分。同文件、同来源、不同 key 并发只产生一次效果，末行失败整批回滚。

## 单位、来源与时间边界

预览使用 MD `previewToBase`／reference 纯读入口；原 `toBase` 委派同一算法后才登记单位使用。成功库存事实在原事务登记基础单位，和原商品维护行锁串行；后续失败全部回滚。预览后基础单位合法变化会使确认返回 STALE，不以旧快照继续入库。

采购 get/list/progress 复用归属层只读数量投影，国内收货表单读取原 progress 中的未交量，保留合格／待检／破损及编辑字段。出口和发运来源展示采购、供应商、SKU 和已维护维度，未知重量／体积保持 null，GET 不登记单位使用或业务事件。

只有来源日期的期初在途保留“时刻未知”，不制造 UTC 午夜。LGS／RTN 的实际时间通过 SYS `CountryCalendar.day` 统一换算国家业务日；计划时间和节点使用同一国家时区工具保留 instant 和毫秒。明确 LocalDate 不被重新转换，历史未知确认人／时刻不猜补。

原运输行冻结真实箱数、单位重量和体积，客户端伪造维度不入库；仅全部已知时汇总，否则显示未维护。成本分摊读取同一冻结来源，旧来源不按当前主档补猜。新实收确认在原事务登记真实操作者与时刻，确认后元数据不可改。

## 经营统计、分类与预警

需求统计由 SAL 的 `SalesStatsApi` 按审批通过时刻、国家时区、基础数量及取消量计算。草稿、待审和全取消不计；批准未发货仍计，国家订单去重，仓库按分仓拆分。分仓合计严格等于订单有效数量，未分配值如实显示，正常已审批订单为零。

分类规则支持国家／门店／仓库、周期、库存与订单联合条件、优先级和有效期，同优先级冲突拒绝。结果冻结规则版本、期间、库存／在途、订单及命中依据；下钻读取计算时证据。国家模板只复制规则配置并要求当地复核，不自动激活。

`StockAlertEvaluator` 由上下限保存及持久 `INV_STOCK_CHANGED` 消费调用，覆盖入出库、预留／释放、冻结／解冻、调拨和盘点。分类消费销售与库存事件，并由同一 SYS worker 重算。重复事件不重复创建派生事实，不伪造业务用户身份。

补货建议／申请／决定／关联／关闭使用真实采购或调拨实收；关联执行行不能重复占用。GET 不推进状态，建议不会自动创建采购单。跨国及父子行关系通过原外键和来源权限保护。

## 工作台与真实页面

原 `WorkItemProvider` 汇合各模块待收货、待派送／实收、待出库、签收差异、到账、逾期和退货待办。延误／暂缓复查复用原任务体系，数量、列表和来源单使用相同范围。看单、抄送和限时代理不扩大原字段或数据权限。

创建表单使用共享完整分页，保留所有业务字段；旧国家、账套、订单或登录响应不得覆盖新选择。门店范围不隐含 BOOK 范围，销售账套候选由所选仓库授权交集确定，多个候选需明确选择。采购供应商来源国和币种独立于 MX 经营归属。

销售附件按原字段组和读写权限挂载，普通销售文件与付款凭据分别保护；取消／分仓／关闭仍调用原归属动作，保留来源 IDs、版本、期间和实际意图。物流“去实收”复用原幂等命令，同来源裸重开返回原单，携带新业务字段的重复创建拒绝。

## 验证方法

- 真实 PostgreSQL 使用完整 Flyway 和原业务服务，覆盖 `ReleaseInventoryIT`、`OpeningSupplyIT`、`InventoryIT`、`InventoryDocumentsIT`、`SalesIT`、`ReceivablesIT`、`SupplyLogisticsIT` 等既有测试；最终数量以当前 XML 为准。
- 导入覆盖服务端文件 hash、预校验无写入、跨 key 并发、末行失败全回滚、单位快照过期、截止日来源与后续业务续接。
- 库存／销售覆盖数量守恒、成本累计尾差、国家／门店／仓库隔离、关期拒绝、销售分仓显式日期、重复消费及撤权后重放。
- 来源展示及物流覆盖历史未知值、国家日跨月正反边界、冻结维度、来源余量、数量和 COST 遮罩；GET 无库存／事件／单位写入。
- 前端调用原 Vue setup／handler 做分页、权限引用、请求序列、空价格、时区和幂等意图回归，再执行完整 `npm test`、构建和契约检查；不复制业务算法计算期望值。
- 原页面按实际岗位执行录入、审核、收发货、往来及下钻；表单打开、查询读回、API 准备和实际执行分开统计。截图及数据库事实私有保留，旧结果不可重贴新制品身份。

## 复用、兼容与后续边界

库存只从 `InventoryApi` 写入，销售统计归 SAL，往来归 AR/AP，源数量归 PUR/LGS，导入不自建业务引擎。编号、授权／期间、幂等、审计、outbox 和后台任务继续使用原实现。新增迁移保留旧事实，完整 schema 审计不得忽略未知表。

Mock 保留独立演示和原回归，生产不接管或双写。旧成本缺依据继续标记待复核，旧确认人／时间未知不回填，私有附件和演练产物不擅自清理。实际业务资料、期初及财务放行依 [通用启用清单](../../deploy/production/launch-readiness.md) 逐项确认，未知金额不补零。
