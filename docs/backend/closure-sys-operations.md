# 运行交付实现与验证方法

本文提供公开源码的运行和恢复边界，不包含生产主机、数据库／会话／单据身份、运行余额或现场收据。当前源码与已部署制品的对应关系见 [发布清单](../releases/2026-10-20-source-binding.json)。详细执行日志、截图和事实核对保存在非公开受控位置，旧结果保留原制品归属。

## 已有运行实现

- 部署复用 `application-verified`／`gateway-verified` 制品入口、独立 Compose backend 网络及运行／迁移秘密。应用 UID10001、网关 UID101、只读根和最小能力保持现有配置。
- `MigrationMain` 核验精确目标数据库，分离 owner／runtime，禁止 clean／baseline／乱序；长期应用固定 Flyway-off，拒绝挂载 owner 秘密。运行角色校验高权限成员关系、DDL 权限和关系所有权。
- readiness 核验数据库、私有 bucket、银行密钥、jobs 及明确 worker assignment；健康成功不等于业务配置、权限或恢复已验收。
- worker 使用原租约、持久执行意图与唯一结果，重试必须重新核验本人当前会话和权限。无业务权限技术身份与管理员分离；财务尚未启用时关闭会计 worker。
- 完整 schema 合同覆盖全表、列、约束、函数、触发器、RLS 和停写门。每次新增迁移同步版本与合同，未知结构使检查失败，不能忽略未知表获得通过。

## 可重现验证

1. 后端在新的隔离副本执行 `./mvnw clean verify -Ppg-it`，核对测试 XML、源码清单、共享 HTTP fixture 和所有迁移；真实 PostgreSQL 与纯 Java 分开统计。
2. 前端执行完整测试、类型检查、生产构建及契约核验，记录 dist 逐文件摘要；重新构建后的制品不能沿用旧浏览器证据。
3. 运行 `jxc-server/scripts/m5/tests` 运维回归，覆盖精确目标、秘密边界、目录合同、失败关闭、并发及回滚。需要 Docker／真实对象存储的测试单列，未运行不计通过。
4. 从应用／网关镜像抽取 jar 和 dist，与已测制品逐字比对；核验架构、非 root、只读根、runtime-only、Flyway-off、HTTPS 正确 CA 和错误 CA 拒绝。
5. 使用明确归属的新隔离资源执行真实 worker 终止、租约到期及重启，确认单结果／通知、当前撤权拒绝、本人新会话重试和失败／积压告警。
6. 按准确名称、UUID label 和拥有者清理本次资源，并独立核验；清理失败、超时或诊断异常不能标通过。不清理无关容器、卷，不运行 prune。

## 恢复核心与约束

逻辑恢复复用原 M5 停写门、backup、加密／解封、`guarded_restore`、完整 verify 及 replay，不建立第二套恢复算法。隔离前缀和精确白名单在执行前及持有目标 guard 后再次核验；目标保持 FROZEN，不自动开放写入。

分别演练基础资料／附件机制和非空财务事实。全表、序列、引用附件、冻结账单关联与凭证来源图均核对原摘要；不能将空财务表目录或空表 hash 称为完整财务恢复。源保留、源丢失、源秘密可用与不可用分别说明。

受控源恢复窗口先明确暂停全部操作，按精确进程与 CAS mode／batch／epoch 冻结，真实停止失败仍需尝试准确重冻。无法确认时报告 UNKNOWN，不自动开门。源恢复前比较业务事实，写门／日志及相关技术序列的已知变化单列，不忽略其他未知对象。

物理 PITR 使用真实基备、连续 WAL、目标时刻前后事务及解封验证。合成事务 marker 和本机恢复耗时只证明机制，不证明生产故障域、RPO 或 RTO。生产目标需要独立准确白名单与身份保护，不能放宽原 M5 前缀。

## 任务与页面验收

任务重登录验收保留原 FAILED、本人退出旧会话、重新登录、显式 retry、成功结果和下载的连续证据。只读数据库补证用于核对唯一执行意图和结果，不能代替实际 UI 操作；持久 JSON 摘要与下载 CSV 摘要分别标注。

A01–A38 与第二国家／门店按当前 jar、前端、国家及实际操作者记录。API 准备、历史业务写入、当前页面读回和真实新命令分别统计；禁用按钮或表单打开不能代替实际重复命令、审批或付款验收。

## 部署与财务边界

[通用部署手册](../../deploy/production/README.md) 复用原 Compose、HTTPS、秘密文件和资源预算；[启用清单](../../deploy/production/launch-readiness.md) 集中管理每个环境的待确认输入。生产现场配置与原始收据不进入公开仓库。

普通业务按原 ACTIVE 国家／账套和 OPEN 期间开放，数据／字段权限、审批、来源额度和幂等继续生效。MX 经营归属不限制中国供应商和 CNY 采购。真实主档、期初和人员由业务补齐；未知值不补零，不虚构交易验收。

财务记账、冲销、结账和反结账保持独立授权，会计 worker 在未启用时关闭；缺已确认账单对应的采购成本仍可确认，但该来源暂停自动记账。生产材料校验始终保留能力边界，不将健康或材料检查等同于生产放行。

## 运行责任与维护债务

每个环境需要明确 DNS／证书续期、最终镜像审核、人员／并发／附件规模、磁盘／积压告警、停写窗口、备份保留、RPO／RTO、独立密钥保管和恢复责任。内部告警事实不代替外部投递和值守验收。

默认备份位于独立故障域；明确批准临时本机策略时按现有 `LOCAL_ONLY_TEMPORARY` 门禁执行，不承诺整机丢失可恢复。未知真实资料、未测容量和未完成的故障域恢复继续列待确认，不能用合成结果代替。

历史日志、失败记录、源码 pin 和同包证据保持各自归属，在私有备份中保存；公开文档不公布现场事实，也不据此扩大自动凭证或恢复能力宣称。
