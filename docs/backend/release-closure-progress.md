# M0–M5 一期收口能力与验证说明

本文汇总公开源码的实现边界和可重现验证方法。生产主机、人员、数据库身份、业务余额、截图及现场执行收据保存在非公开受控位置；不将历史过程状态当作当前生产放行结论。精确源码与制品绑定见 [发布清单](../releases/2026-10-20-source-binding.json)。

## 现有实现与复用

1. **权限与基础约束**：门店账户创建委派 MD 资金账户服务；组合授权通过原 `PUT /sys/users/{id}/grants` 在同一事务中保存角色与范围，沿用上界、版本和排他锁。启动校验覆盖准确系统前缀、高权限成员关系与关系所有权；草稿／启用／停用国家分别控制配置、交易和历史只读。
2. **金额及成本**：期初缺失／null 金额拒绝，明确零保留原语义；AP 核对纳入冻结汇差及其冲销。退回后补成本复用累计分配及末笔尾差，商品重量／体积持久化，未知分摊依据拒绝。采购和销售人工单价未知时不默认零。
3. **国家和配置**：模板仅复制允许的配置和规则版本，排除交易、余额、人员绑定及银行资料；目标敏感配置当地复核。字典、主档、编号、审批和成本确认沿用原入口，bootstrap 拒绝已有业务／主档数据。
4. **统一导入与期初**：`/sys/imports` 使用服务端文件 hash、批次、来源和目标映射。主档调用原维护服务，库存只走 `InventoryApi`，AR/AP/GL 与未完采购／在途由各模块处理；子账和总账独立录入核对。确认原子执行，跨 key 并发不能重复导入。
5. **库存经营与待办**：有效订单统计归 SAL，原 outbox、`INV_STOCK_CHANGED` 和 `WorkItemProvider` 更新分类、预警及运营待办。补货与真实采购／调拨执行关联，抄送不增权，代理不继承额外范围。分仓合计严格等于有效数量，正常已审批订单未分仓为零。
6. **财务配置与业务导出**：原报表模板维护行／科目映射和版本复核，`JobService/JobHandler` 承担账簿与业务导出。AP 默认确认账单形成应付；可配置收货后建草稿，不能自动确认或记账。本人重新登录后的任务重试使用本人当前会话重新授权。
7. **部署和恢复**：模块化单体及原前端通过受管容器、HTTPS、非 root、只读根、独立迁移和 runtime-only/Flyway-off 运行。M5 审计、停写门、备份、加密、恢复和准确白名单复用原核心，不能放宽隔离前缀或忽略未知结构。

详见 [系统与配置](closure-sys.md)、[库存与业务](closure-inventory.md)、[财务](closure-finance.md) 和 [运行验证](closure-sys-operations.md)。

## 采购成本与账单本金

成本可继续确认；缺已确认账单的明确对应时，暂停该来源自动记账，显式关联并冻结本金后再生成。AP 来源额度和冻结关联参与原 FIN 事务，`AccountingAmounts.split` 与唯一 renderer 分配累计尾差，不以当前汇率重新解释来源。

待关联、草稿关联和冻结状态分别保留，币种／单位／来源不符时拒绝。数据库双向约束保护身份、容量及冻结关系，经济金额由原业务归属模块与唯一解释算法计算；不通过省略应付行获得表面平衡。旧已解释来源只读，不回填重算历史凭证。

## 验证方法和证据边界

- 在新的隔离 PostgreSQL 中执行 `jxc-server/./mvnw clean verify -Ppg-it`，保留各测试 XML、参数展开、失败及重试记录，区分真实 PG 与纯 Java。
- 在 `jxc-web` 执行 `npm ci`、`npm test`、`npm run build` 和原契约生成器 `--check`，确认生产构建不启用 Mock。测试数量以当前实际输出为准。
- 使用 M5 运维回归核对完整目录、RLS／外键／全表停写门、目标身份、并发和失败回滚；新迁移同步合同及支持版本。
- 浏览器按 A01–A38、第二国家和第二门店逐项记录；API／SQL 准备、表单打开、查询读回和实际业务写入分别标注。新制品不得借用旧图宣称已执行。
- 分别验证 worker 真实终止恢复、逻辑恢复、非空财务图与物理 PITR；注明源是否保留、秘密是否可用、对象范围及精确制品。合成演练不证明生产 RPO/RTO。
- 发布与线上对应关系采用源码逐文件和 jar／dist 字节核对，公开清单不包含生产秘密或运行数据。详细原始日志、截图和数据库事实由有权人员在非公开位置复核。

## 普通业务与财务启用

经营端国家、账套和开放期间通过原配置服务启用，不改变供应商来源国或采购币种。中国采购可归属于 MX 收货经营端，无需额外中国账套。未知期初不填零，已启用账套不等于已确认零余额。

普通业务开放时继续原权限、审批、幂等和期间规则；财务未获授权时维持记账／冲销／结账／反结账限制，会计 worker 关闭。真实主档、价格、成本和来源不足时，由相应能力拒绝，不能虚构交易验收。

部署输入及责任确认使用 [通用部署手册](../../deploy/production/README.md) 和 [启用清单](../../deploy/production/launch-readiness.md)。生产性能、容量、外部告警、备份故障域、RPO/RTO 和源主机丢失恢复需要各环境单独完成。

## 兼容退出和维护债务

优先修改原服务与页面；统一资金账户服务替代裸写入，原组合授权替代串行授权意图，原独立 PUT 保留独立操作语义。没有另建权限、库存、成本、总账或恢复引擎。

Mock 保留独立演示和原回归，待相关调用和演示用途全部退出再删除。缺历史成本的兼容分支保留明确估算标记；旧确认人／时刻未知不猜补。Vite 大包、密集旧代码、私有孤儿附件和演练产物按实际归属维护，不擅自清理。

外部 AI 未配置时明确不可用；完整历史迁移、外部付款执行、税务和外部平台接口继续独立立项。自动凭证验证以现有本位币总账为界，冻结原币来源可追溯，不扩大为完整原币凭证核算；未收采购的跨期过渡资产若扩展，需先确认会计规则。
